# Feature Specification: 潮回り表示（ダイビング記録・予定）

**Feature Branch**: `007-tide-phase-display`

**Created**: 2026-06-12

**Status**: Implemented

**Input**: User description: "潮周り表示 ダイビング記録のDBには保存せずに JSの処理だけで実装したい　次のダイビング予定も保存したら潮回りが表示されるようにしたい"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ダイビング記録での潮回り表示 (Priority: P1)

ダイバーであるユーザーは、登録済みのダイビング記録を一覧・詳細で見るときに、その日の潮回り（大潮・中潮・小潮・長潮・若潮）を自動表示で確認できる。潮回りは流れ・透明度・魚の活性に影響する基本的な海況情報であり、紙のログブックにも記入欄がある定番項目のため、「あの日は大潮だった」を後から振り返れるようにする。

**Why this priority**: 蓄積済みのダイビング記録すべてに対して即座に価値が出る部分であり、これ単体で「過去のダイビングの潮回りを振り返れる」という価値が成立する。潮回りの算出ロジック自体もこのストーリーで確立される。

**Independent Test**: 新月にあたる日付のダイビング記録を表示し、潮回り「大潮」が一覧・詳細に表示されることで単独テスト可能。

**Acceptance Scenarios**:

1. **Given** 新月当日の日付を持つダイビング記録が登録済み, **When** その記録の詳細を表示する, **Then** 潮回り「大潮」が表示される
2. **Given** 上弦の月にあたる日付のダイビング記録が登録済み, **When** 記録一覧を表示する, **Then** その記録に「小潮」が表示される
3. **Given** 異なる日付のダイビング記録が複数件登録済み, **When** 記録一覧を表示する, **Then** 各記録にそれぞれの日付に応じた潮回りが表示される
4. **Given** ダイビング記録が登録済み, **When** TOP ダッシュボードを表示する, **Then** 「最近のダイビング」リストの各記録に潮回りが表示される

---

### User Story 2 - ダイビング予定での潮回り表示 (Priority: P2)

ユーザーは、次のダイビング予定を保存すると、その予定日の潮回りを一覧・詳細で確認できる。「大潮を狙って潜る」「小潮の穏やかな日に初心者と潜る」のように、潮回りはダイビング計画の判断材料になるため、保存した予定に自動で表示する。

**Why this priority**: ユーザーの依頼にある「次のダイビング予定も保存したら潮回りが表示される」に応える部分。算出ロジックは User Story 1 で確立されたものを予定日に適用するだけのため、独立した増分として後続できる。

**Independent Test**: 満月にあたる未来の日付でダイビング予定を保存し、保存後の予定に「大潮」が表示されることで単独テスト可能。

**Acceptance Scenarios**:

1. **Given** ダイビング予定の作成フォームを開いた状態, **When** 満月にあたる日付で予定を保存する, **Then** 保存後の予定の一覧・詳細に「大潮」が表示される
2. **Given** 保存済みのダイビング予定, **When** 予定日を別の潮回りにあたる日付へ変更して保存する, **Then** 変更後の日付に応じた潮回りに表示が更新される
3. **Given** 直近のダイビング予定が保存済み, **When** TOP ダッシュボードを表示する, **Then** 「次の予定」カードに予定日の潮回りが表示される

---

### Edge Cases

- 潮回りの区分が切り替わる境界の日付でも、必ず 5 区分のいずれか 1 つに分類され、未分類・エラー表示にならない
- 月齢は近似計算で求めるため、公式の潮汐表・潮見表と区分が前後 1 日程度ずれる場合がある → 参考情報として許容する（Assumptions 参照）
- 日付が取得できない場合 → 潮回りを表示せず、画面の他の情報表示は妨げない
- 遠い過去・未来の日付でも計算が破綻しない（記録・予定それぞれの既存の日付制約の範囲で正しく動作する）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはダイビング記録の一覧・詳細および TOP ダッシュボードの「最近のダイビング」リストで、各記録の日付に対応する潮回りを表示する
- **FR-002**: システムはダイビング予定の一覧・詳細および TOP ダッシュボードの「次の予定」カードで、各予定の予定日に対応する潮回りを表示する。予定の保存・更新後は変更後の日付で再計算した潮回りが表示される
- **FR-003**: 潮回りは「大潮」「中潮」「小潮」「長潮」「若潮」の 5 区分とし、月齢に基づく一般的な区分に従って日付のみから決定する
- **FR-004**: 潮回りは表示の都度算出する導出値とし、保存しない。ダイビング記録・予定の既存データ構造に潮回りの項目を追加しない
- **FR-005**: 潮回りの算出は外部サービスや外部データの取得に依存せず、日付からの計算のみで完結する
- **FR-006**: 同一の日付に対しては常に同一の潮回りを返す（決定的な算出）
- **FR-007**: 日付が取得できない場合は潮回りを表示せず、画面の他の情報表示を妨げない
- **FR-008**: 潮回りの区分はテキストラベルで表示し、色のみで区分を伝えない

### Key Entities

- **潮回り（TidePhase）**: 大潮・中潮・小潮・長潮・若潮の 5 区分。日付（月齢）から導出される値であり、保存される属性ではない
- **ダイビング記録（既存）**: ダイビング実施日を持つ。潮回り表示の対象
- **ダイビング予定（既存）**: 予定日を持つ。潮回り表示の対象

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 登録済みのすべてのダイビング記録・予定に、ユーザーの追加入力や追加操作なしで潮回りが表示される（手入力ゼロ）
- **SC-002**: 新月・満月にあたる日付では「大潮」、上弦・下弦にあたる日付では「小潮」が表示される
- **SC-003**: 連続した約 1 ヶ月（1 朔望周期）の日付に対して 5 区分すべてが出現し、「小潮 → 長潮 → 若潮 → 中潮」の順序で循環する
- **SC-004**: 潮回り表示の追加によって、記録・予定の登録・閲覧の既存の操作手順は変わらない（追加の入力項目 0）

## Assumptions

- 「潮周り（潮回り）」は、日本のダイビング・釣りで一般的な月齢ベースの 5 区分（大潮・中潮・小潮・長潮・若潮）の表示と解釈した
- ユーザー指定により、潮回りは保存せず表示時の計算のみで導出する（記録・予定のデータ構造の変更は行わない）。外部の潮汐サービス・データ取得にも依存しない
- 月齢は平均朔望月（約 29.53 日）に基づく近似計算で求める。公式の潮汐表と区分が前後 1 日程度ずれる可能性は、参考情報の位置づけとして許容する
- 潮回りの区分は月齢のみで決まり、観測地点（海域）に依存しないものとする。地点別の補正は行わない
- 表示対象はダイビング記録とダイビング予定それぞれの一覧・詳細画面、および TOP ダッシュボードの「次の予定」カード・「最近のダイビング」リストとする（「最近のダイビング」は追加要望 2026-06-13）
- 満潮・干潮の時刻や潮位の数値表示はスコープ外とする（区分名の表示のみ）
- フォームで日付選択中のリアルタイム潮回りプレビューはスコープ外とする（保存済みの記録・予定への表示のみ。将来拡張の候補）
- 既存のダイビング記録機能（002）とダイビング予定機能（004）が日付を持つことを前提とする
