# Quickstart: 潮回り表示の動作検証

実装完了後に機能が end-to-end で動くことを確認する手順。算出仕様・対応表は [data-model.md](data-model.md)、要件は [spec.md](spec.md) を参照。

## 前提

- ルートで `make supabase-seed` 済み（テストユーザーでログインできること）
- Supabase ローカル環境が起動済み（`supabase start`）。**マイグレーションの追加適用は不要**（スキーマ変更なし）

## セットアップ

```bash
# フロント開発サーバー起動のみ
make front-dev
```

## 自動テスト

```bash
# tide.ts 単体テスト + 表示統合したコンポーネントのテスト
make front-test

# 型チェック・lint を含む全チェック
make front-validate
```

期待結果: `tide.test.ts`（[data-model.md 4 節](data-model.md) の基準日付 8 件・不正入力 → null・30 日分の循環順序）と、DiveCard / DiveDetail / PlanList / NextPlanCardView の各 `*.test.tsx` がすべてグリーン。

## 手動検証シナリオ

テストユーザーでログインする。日付は [data-model.md 4 節](data-model.md) の基準日付を使うと期待値が確定する。

### 1. ダイビング記録での潮回り表示（User Story 1 / P1）

1. `/dives/new` で日付 `2000-01-07` のログを登録 → 記録一覧のカードと詳細（`/dives/[id]`）に「大潮」が表示される
2. 日付 `2000-01-13` のログを登録 → 「小潮」が表示される
3. 一覧で 2 件を見比べ、各記録にそれぞれの日付の潮回りが付いている
4. TOP ダッシュボードを開く → 「最近のダイビング」リストの各記録にも潮回りが表示される

### 2. ダイビング予定での潮回り表示（User Story 2 / P2）

予定日は未来日付のため、月齢カレンダー（潮見表サイト等）で直近の新月または満月の日付を確認して使う。

1. `/plans/new` で新月（または満月）にあたる未来日付の予定を保存 → 予定一覧・予定詳細（`/plans/[id]`）に「大潮」が表示される
2. TOP ダッシュボードを開く → 「次の予定」カードにも同じ潮回りが表示される
3. 予定日を 1 週間後（上弦・下弦付近）に編集して保存 → 表示が「小潮」前後の区分に更新される

### 3. 表示されない場合の確認（FR-007）

1. 潮回り以外の項目（場所・深度等）が従来どおり表示されており、潮回り追加でレイアウトが崩れていないこと

### 4. アクセシビリティ

```bash
make front-test-a11y
```

期待結果: 記録一覧・記録詳細・予定一覧・予定詳細・TOP の各画面で axe-core 違反 0 件。潮回りラベルがテキストとして読み上げ対象に含まれる（色のみの区別でない）。
