# Feature Specification: ダイブログ検索・フィルタ強化

**Feature Branch**: `013-dive-search-filters`

**Created**: 2026-06-18

**Status**: Draft

**Input**: User description: "検索・フィルタ強化 — 期間・深度範囲・ダイブタイプ。現状は番号 / 日付 / 場所のみ"

## Clarifications

### Session 2026-06-18

- Q: 深度範囲フィルタ適用時、最大水深が未記録（null）のログの扱いは？ → A: 除外する。下限・上限のどちらかでも指定されたら、最大水深が未記録のログは結果から除外する（011 の平均透明度と同じ null 除外方針と一貫）
- Q: 追加するフィルタ（期間・深度・ダイブタイプ）入力 UI の出し方は？ → A: 折りたたみ可能な「詳細条件」パネルに格納する。既存の番号・ポイント名は常時表示のまま、追加フィルタは開閉式パネルに収め、適用中のフィルタは折りたたんだ状態でも分かるように示す

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 期間（日付範囲）でログを絞り込む (Priority: P1)

ダイバーであるユーザーは、ダイブログ一覧で「いつからいつまで」の期間を指定して、その範囲に潜ったログだけを絞り込める。現状は単一の日付でしか絞れず、「去年の夏」「この 3 ヶ月」といった範囲での振り返りができないため、開始日・終了日で範囲指定できるようにする。

**Why this priority**: 期間での振り返りはログ閲覧で最も頻度が高く、単一日付フィルタの最大の不満点。これ単体で「特定シーズンのログを一覧する」という価値が成立する。

**Independent Test**: 異なる日付のログが複数ある状態で開始日・終了日を指定し、その範囲内のログだけが表示される（範囲外が除外される）ことで単独テスト可能。

**Acceptance Scenarios**:

1. **Given** 複数の日付のログがある, **When** 開始日と終了日を指定して検索, **Then** その期間内（両端を含む）のログだけが表示される
2. **Given** 期間を指定した状態, **When** 開始日のみ指定（終了日空）, **Then** 開始日以降のログがすべて表示される
3. **Given** 期間を指定した状態, **When** 終了日のみ指定（開始日空）, **Then** 終了日以前のログがすべて表示される
4. **Given** 開始日が終了日より後, **When** 検索しようとする, **Then** 入力エラーが示され、破綻した結果にならない

---

### User Story 2 - 深度範囲でログを絞り込む (Priority: P2)

ユーザーは、最大水深の範囲（下限・上限）を指定して、特定の深さ帯のログを絞り込める。「30m 以深のディープなログ」「初心者向けの浅いログ」といった深度での振り返りを可能にする。

**Why this priority**: 深度はダイバーの関心が高い軸だが、期間ほど日常的ではないため P2。期間フィルタと独立して機能する。

**Independent Test**: 最大水深の異なるログが複数ある状態で下限・上限を指定し、その範囲の最大水深を持つログだけが表示されることで単独テスト可能。

**Acceptance Scenarios**:

1. **Given** 最大水深の異なるログがある, **When** 下限と上限を指定して検索, **Then** 最大水深がその範囲内（両端を含む）のログだけが表示される
2. **Given** 深度範囲を指定, **When** 下限のみ指定, **Then** その深さ以上のログが表示される（上限のみも同様に上限以下）
3. **Given** 下限が上限より大きい, **When** 検索しようとする, **Then** 入力エラーが示される

---

### User Story 3 - ダイブタイプでログを絞り込む (Priority: P3)

ユーザーは、ダイブタイプ（ボート / ビーチ等の既存の種別）を選んで、その種別のログだけを絞り込める。

**Why this priority**: 絞り込み軸として有用だが、期間・深度に比べ利用頻度は低めのため P3。単独で機能する。

**Independent Test**: 異なるダイブタイプのログがある状態で 1 つの種別を選び、その種別のログだけが表示されることで単独テスト可能。

**Acceptance Scenarios**:

1. **Given** 異なるダイブタイプのログがある, **When** ダイブタイプを 1 つ選んで検索, **Then** その種別のログだけが表示される
2. **Given** ダイブタイプを選択, **When** 「指定しない」に戻す, **Then** ダイブタイプによる絞り込みが解除される

---

### Edge Cases

- 各フィルタは AND で組み合わさる（期間 ＋ 深度 ＋ ダイブタイプ ＋ 既存の番号 / ポイント名を同時指定 → すべてを満たすログのみ表示）
- どのフィルタにも一致しない場合 → 「該当するログがありません」を表示し、フィルタ解除の導線を示す
- フィルタ未指定（すべて空）→ 全ログを従来どおり表示する
- 範囲入力の片側のみ指定 → 開いた範囲（以上 / 以下）として扱う
- 不正な範囲（開始 > 終了、下限 > 上限）→ 検索を実行せず入力エラーを示す
- 深度範囲を指定したとき、最大水深が未記録（null）のログ → 結果から除外する
- フィルタ適用後もページネーション（追加読み込み）が絞り込み条件を維持する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ユーザーはダイブログ一覧で、開始日・終了日による期間でログを絞り込めなければならない（両端を含む。片側のみの指定は開いた範囲として扱う）
- **FR-002**: ユーザーは最大水深の下限・上限による深度範囲でログを絞り込めなければならない（両端を含む。片側のみ可）。下限・上限のいずれかが指定されたとき、最大水深が未記録のログは結果から除外しなければならない
- **FR-003**: ユーザーはダイブタイプ（既存の種別の選択肢）でログを絞り込めなければならない
- **FR-004**: 既存の絞り込み（ダイブ番号・ポイント名）は維持され、新しいフィルタと併用できなければならない
- **FR-005**: 複数のフィルタは AND（すべて満たす）で組み合わさらなければならない
- **FR-006**: 開始日 > 終了日、深度下限 > 上限などの不正な範囲は検索を実行せず、ユーザーに分かるエラーを示さなければならない
- **FR-007**: フィルタ未指定時は全ログを従来どおり表示しなければならない
- **FR-008**: フィルタ適用結果が 0 件のときは、その旨とフィルタ解除の導線を表示しなければならない
- **FR-009**: 適用中のフィルタ条件は、一覧の追加読み込み（ページネーション）をまたいでも維持されなければならない
- **FR-010**: 適用中のフィルタ条件は、ページの再読み込み・共有（URL）で復元できなければならない
- **FR-011**: ユーザーは適用中のフィルタを一括で解除できなければならない
- **FR-012**: 期間・深度・ダイブタイプのフィルタは折りたたみ可能な「詳細条件」パネルに配置し、既存の番号・ポイント名は常時表示を維持しなければならない。パネルが折りたたまれた状態でも、適用中のフィルタがあることをユーザーが認識できなければならない

### Key Entities *(include if feature involves data)*

- **ダイブログ（既存）**: 検索・絞り込みの対象。本機能で参照する属性は潜水日・最大水深・ダイブタイプ・ダイブ番号・ポイント名（サイト名 / 自由入力）。スキーマ変更はない（既存カラムでの絞り込みのみ）
- **検索フィルタ条件**: ユーザーが指定する絞り込み条件の集合（期間 from/to・深度 min/max・ダイブタイプ・ダイブ番号・ポイント名）。保存はせず、URL 等で表現する導出的な状態

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは期間・深度・ダイブタイプのいずれの軸でも、目的のログ群を 1 回の絞り込み操作で表示できる
- **SC-002**: 複数フィルタを同時指定したとき、表示結果はすべての条件を満たすログと 100% 一致する（手動確認との不一致 0 件）
- **SC-003**: 不正な範囲入力（開始>終了 等）で破綻した結果や空白の取りこぼしが発生しない（破綻 0 件）
- **SC-004**: フィルタ条件を含む URL を共有・再読み込みすると、同じ絞り込み結果が再現される
- **SC-005**: 絞り込み結果が 0 件でも、ユーザーは迷わずフィルタを解除して全件表示に戻れる

## Assumptions

- 本アプリの既存の認証機能（001-auth）とダイブログ機能（002-dive-log-crud）、ダイブサイトマスタ（011）が利用できることを前提とする
- 既存の単一「日付」フィルタは、期間（開始日・終了日）フィルタに**置き換える**（単一日は開始=終了で表現できるため後退ではない）
- 深度範囲は**最大水深（max depth）**を対象とする（平均水深は対象外）
- ダイブタイプの選択肢は既存のダイブタイプ種別を流用し、選択は**単一**とする（複数同時選択はスコープ外・将来拡張）
- フィルタ状態は URL のクエリパラメータで表現し、既存の検索（番号・ポイント名）と同じ仕組みに乗せる
- 絞り込みは本人のログのみが対象（既存のアクセス制御に従い、他人のログは対象外）
- 絞り込み・ソートの基本挙動（日付降順表示・ページネーション）は既存を踏襲する

## Dependencies

- 既存のダイブログ一覧・検索 UI（番号 / 日付 / ポイント名）に新しいフィルタ項目を追加する形で構築する
- ポイント名検索は 011（ダイブサイトマスタ）でサイト名・自由入力名の双方一致に対応済み。本機能はそれを変更せず、期間・深度・ダイブタイプの軸を追加する
